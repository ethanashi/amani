# Studio JSON-RPC presentation protocol

Node 24 `bridge.mjs` transports newline-delimited JSON-RPC over stdio to a workspace owner on a mode-600 Unix socket in a mode-700 owner directory. `daemon.mjs` constructs the real `EngineService`; `protocol.mjs` maps its canonical records to `src/types.ts`. All mutations and scientific labels stay in the engine. There is no production fixture fallback. Errors/disconnection are visible; clients never automatically retry mutations.

The raw service remains available at `packages/omb-investigate/src/engine-sidecar.ts`, with its original schemas. Studio calls the presentation adapter:

- `investigations.list/get` map verified journal records and actual phase/result state. `create` takes question, project and a file-check token, materializes only the pinned selected files, and constructs a real InvestigationSpec. Raw `{spec}` is also accepted for engine clients. Pause/cancel request a safe phase boundary; resume is explicit. System-bug resume passes the engine's checkpoint token plus the owner's concrete repair reason, without resetting budgets.
- `ledger.tail` returns stable sequence-derived IDs and full payloads for inspection; `ledger.entry` pushes new records. Provider attempts retain typed outcomes/decisions, including family-violation, refusal and non-compliance. Assistant attempts use `provider.attempt` notifications rather than pretending to be investigation journal entries.
- `inbox.list/act` expose real owner plan requests, pauses/needs-you, triage parks and amendment-request drafts. Plan approval binds the exact recorded plan hash. Acknowledgment never grants a label or approves a plan. Draft amendments are journaled owner requests, not executable model mutations. Endorsement is unavailable without the paper pipeline.
- `assistant.ask {investigationId, requestId, question}` echoes both scope identifiers in its answer. The renderer drops stale completions and mismatched scope; citation IDs must belong to that investigation. It uses the configured assistant chain and returns host-rendered verified ledger excerpts/citations. Failures are explicit, with provider attempt notices. No answer is invented as a fallback.
- `providers.get` includes read-only warnings. Studio removes them from editable config. `providers.set {config,validateOnly}` uses the real validator; validateOnly never saves. `providers.defaults` supplies defaults for explicit repair, without saving. `providers.models` is advisory/free text; `providers.test` is an explicit model call (tests substitute offline adapters). Key material never enters these RPCs.
- `settings.get/set` persists allowlisted nonsecret preferences. Current scheduler pools/compute admission are read-only. `library.list` lists configured local CSV/TSV files, with `rows: null` until a trusted count exists. `data.check` pins readable file bytes; it does not certify a scientific contract. Browser metadata is insufficient for real staging.
- `paper.download` serves only files in the completed engine deliverable manifest, contained within the engine root, with matching SHA-256. No arbitrary client file paths. The current engine publishes report.md, paper-input.json, diagnostics.json, integrity.json and manifest.json. A PDF preview is possible only if the real engine publishes paper.pdf; Studio does not synthesize one.
- `system.status` reports actual scheduler jobs, host memory/load/disk, last explicit model probes and launcher attestation. The `configErrors` array remains visible on the Board with Settings repair. Launcher status is cached across clients and reconnects; `{refreshLauncher:true}` explicitly refreshes it, coalescing in-flight checks. Missing installations never invoke attest; the owner-only install command is displayed, never executed (see SECURITY.md). Invalid provider configuration does not block status or Board access. No availability is inferred from a provider merely being enabled.

On reconnect Studio reloads snapshots and journal subscriptions. The workspace owner exits after 1.5 seconds without clients when no investigations are running. Active work survives client/bridge termination. A launch lock serializes stale-socket replacement; the bridge never terminates a process named in a lock/PID file. Engine crash closes the socket and triggers bridge restart; durable state requires explicit owner resume.

`tests/fixtures/service.mjs` is only for screenshots and the original 200-record regression. `tests/fake-daemon.ts` runs the real service/phase machine with offline provider, execution and certification doubles. Neither is packaged in the app. Production has no fixture control methods.

The renderer validates JSON-RPC envelopes, every presentation result schema and notification payload before dispatch. Invalid messages raise a recoverable error and retain the last valid snapshot. Startup failure persists independently of dismissible alerts; Retry reinitializes the transport. A renderer error boundary provides a final reconnect action.
